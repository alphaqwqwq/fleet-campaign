# 文档索引

本目录只保存项目自身的设计、规则约束、工程决策和执行记录。原始规则书、模组 PDF、提取文本及其他外部参考资料必须保留在本仓库之外的本地参考目录，不得提交到公开代码仓库。

## 目录

| 目录 | 内容 | 是否可直接驱动实现 |
| --- | --- | --- |
| `00-governance/` | 目录约定、开发流程、提交、质量门禁与文档模板 | 是 |
| `02-rules/` | 已确认规则约束、状态不变量与协议契约 | 是 |
| `04-plans/` | 经确认后可以拆分执行的阶段计划 | 是 |
| `05-execs/` | Plan 下的细粒度执行记录、验证结果和提交证据 | 是 |
| `08-prompts/` | 给开发 Agent、测试 Agent 和 LLM 旁白的受控提示词 | 是 |

开发对话提示词只定位 Plan、Exec 或 Review 的目标文档；完整边界、约束和验收必须写在该稳定文档内。具体格式见 [工作流](00-governance/WORKFLOW.md) 与 [提示词索引](08-prompts/README.md)。

- [网页发布 CI/CD 全流程经验手册](00-governance/RELEASE-CICD-PLAYBOOK.md)：网页发布的标准门禁、发布链路、多网络验收矩阵与已踩坑经验；每个大阶段在本地验证完成后必须实际投放网页并做多人在线验证。

## 文档优先级

当文档结论冲突时，按以下顺序执行：

1. 已确认的规则约束与版本化 Schema。
2. 已接受的 ADR。
3. 已批准 Plan 和处于执行状态的 Exec。
4. 玩法讨论草案。
5. 外部参考资料。

任何需要修改前三级内容的工作，必须先更新 Plan 或新增 ADR，不得在代码中隐式改变约束。
